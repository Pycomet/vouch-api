# Milestone 2: amendments to the spec

`docs/specs/M2.md` is the source of truth for Milestone 2. It was written against PR #2. The repository has moved on since then, and the agent brief adds hard rules. Where the spec and this table disagree, this table wins. Anything not listed here follows the spec.

| # | Spec says | We do | Source |
|---|---|---|---|
| A1 | Migration 0002 | `0003_schema_alignment`, `down_revision="0002_listing_publication_fields"`. The existing 0002 (listing status, review columns) is kept. | brief |
| A2 | Lagos-first; city hard-coded in inventory | Launched cities come from `VOUCH_LAUNCHED_CITIES` (comma list, default `abuja`). No city literal in any query, schema or docstring. A city that isn't launched returns 400; an unlaunched asset returns 404. | brief |
| A3 | The band on `catalogue_items` is the booking guard | `assets.minimum_trust_tier` is the only guard column, and its CHECK widens to `BETWEEN 0 AND 3`. The band sets the default when a listing is created or backfilled: A→1, B→2, C→3. Tier 3 means renter effective tier ≥ 2 **and** `bookings.vendor_approved_at IS NOT NULL`. | owner decision, 30 Oct 2026 |
| A4 | `waiver: boolean`; `paymenttype.protection_waiver` | `damage_contribution: boolean`; the enum value is renamed `damage_contribution`; the snapshot key is `damage_contribution`. The `protection_pool` ledger account is kept. | owner decision, 30 Oct 2026 |
| A5 | Category enum value `other` | Backfilled to the slug `accessory`, to match the request portal. | brief rule 5 |
| A6 | `kyc_profiles.tier` (old: 1 = ID + liveness, 2 = + address) | New tier 1 = ID + liveness + address. Data: old 2 → 1; old 1 → `status='submitted', tier=0, verified_at=NULL` (address not yet verified). CHECK `tier BETWEEN 0 AND 1`. | spec §2.3 |
| A7 | `/catalogue/search`, alongside the existing `/assets` | Both endpoints are kept and share one inventory service. The `/assets` date filter switches to the live booking statuses. | judgement |
| A8 | Policy values the spec doesn't give | Config placeholders, flagged in every step report: `VOUCH_COMMISSION_RATE=0.15`; `VOUCH_DAMAGE_CONTRIBUTION_RATE=0.05` (of rental); a renter cancelling before the start date gets a full refund of everything paid; the delivery fee comes from `assets.fulfilment.delivery_fee` (default 0). | spec gap; pending legal advice |
| A9 | "Atlas ERD" | `docs/erd.svg` is rendered from a Mermaid file generated from `Base.metadata` with `@mermaid-js/mermaid-cli`. Atlas is used only if it's already installed. | judgement |
| A10 | The spec doesn't say where claims, renter freezes, the at-risk flag or OTP challenges live | 0003 adds `bookings.claim_*`, `bookings.at_risk_at` and `users.restricted_at` / `restricted_reason`. 0004 (Step 5) adds `otp_challenges` and `users.phone_verified_at`, and makes `users.full_name` nullable. | spec gap |
| A11 | Spec §2.2 GIN index expression | Postgres rejects it (`array_to_string` is not IMMUTABLE). The identical expression is wrapped in the IMMUTABLE SQL function `catalogue_search_vector(make, model, aliases)`, used by both the index and the `q` filter. | Postgres constraint |
| A12 | Spec §2.6 lists no index on `audit_events` | Added `ix_audit_events_entity (entity, entity_id)` for audit-trail lookups by entity. | judgement |
| A13 | §3.1: no renter withdrawal before confirmation; A8: a renter cancelling before the start date gets a full refund | **Withdrawal (Booking.com model).** A renter may withdraw for FREE while the booking is `requested` (vendor hasn't responded) and while it is `accepted` but not yet paid. → `cancelled_by_renter`, no money moves. Once paid (`confirmed`), a renter cancellation (still only before 00:00 Africa/Lagos on `starts_on`) refunds everything paid MINUS a cancellation fee. The fee = `rental_total × renter_cancellation_fee_rate` (placeholder 0.10), quantized ROUND_HALF_UP to 0.01, **split between the vendor and Vouch**: vendor share = fee × `cancellation_fee_vendor_share` (placeholder 0.50, quantized ROUND_HALF_UP), and Vouch gets the remainder (so the parts always sum to the fee exactly). Both rates are config placeholders pending legal advice and are FROZEN into `price_snapshot` at request time (keys `cancellation_fee_rate`, `cancellation_fee_vendor_share`), like `commission_rate`. Vendor cancellation of a paid booking stays a full refund + reliability penalty (unchanged). | owner decision, 30 Oct 2026; pending legal advice |
| A14 | §3.1: deposit + damage contribution to confirm, rental balance (`balance_captured`) before handover | **Full payment upfront.** The renter pays EVERYTHING (deposit D + damage contribution C + rental R + delivery fee F) in ONE payment to confirm. The event `deposit_captured` is renamed `payment_captured` (accepted → deposit_paid → confirmed, as before); its amount must equal D + C + R + F; it posts ONE balanced group: dr platform_cash (D+C+R+F) / cr renter_deposit_liability D / cr protection_pool C / cr vendor_payable (R+F−K) / cr platform_revenue K. The `balance_captured` event and row are REMOVED; `confirmed + handover_completed` alone (completed pickup record) → `in_progress`. The payment row for this is a new `paymenttype` value `booking` (migration `0004_booking_payment`; the plan's OTP migration becomes 0005 in Step 5). | owner decision, 30 Oct 2026 |
| A15 | §3.2: at risk at T+48h with no contact | **Late return.** A rental is at risk once the return isn't signed by the END of its last rental day: at-risk iff `now >= start_of_business_day(ends_on + 1 day)` (i.e. AT_RISK_AFTER = 0; no 48 h wait). "No contact" in the spec is read as "not returned". | owner decision, 30 Oct 2026 |
| A16 | §3.1: mark lost at T+7d | **Lost.** Unchanged: admin may mark lost from `start_of_business_day(ends_on + 7 days)`. | owner decision, 30 Oct 2026 |
| A17 | §3.1 has no way for a renter to report that the vendor never handed the item over | **Vendor no-show (renter-reported).** New event `report_no_show`, row `confirmed + report_no_show` (renter, party only) → `cancelled_by_vendor`. Guards, all before any write: `now >= start_of_business_day(starts_on)` (else `no_show_too_early`); no completed pickup handover (else `handover_signed`); the vendor has not signed its side of the pickup record (else `vendor_signed_handover`). Effects: a FULL refund with no fee (the same reversal postings as a vendor cancellation of a paid booking, so every booking-scoped account returns to 0.00); `cancelled_at = now`; `cancellation_reason = "vendor_no_show"` (followed by `: <note>` when the renter gives one); audit `booking.cancelled_by_vendor` plus the `vendor.reliability_penalty` row (reason `vendor_no_show`); notify the renter `booking.no_show_refunded`, the vendor `booking.no_show_reported` and ops `ops.vendor_no_show`. Route: `POST /bookings/{id}/no-show` (renter; body `{reason?: str ≤ 500}`). | owner decision, 1 Nov 2026 |
| A18 | §3.4: the money line's part statuses (`due`, `held`, `received`, ...) say nothing for a booking that ended before it was paid | **Money-line wording for bookings closed before payment.** A booking that ends `declined`, `expired`, `cancelled_by_renter` or `cancelled_by_vendor` with no payment ever captured shows `"cancelled"` (instead of `"due"`) for `deposit.status`, `rental.status` and `contribution.status` (when present). `next` stays `"Closed"` / `"0.00"`. | owner decision, 1 Nov 2026 |
