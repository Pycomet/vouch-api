## 2. Migration 0002 — schema alignment

One Alembic revision, reversible. Data migrations for the enum→table moves included.

### 2.1 Reference tables replacing enums

```sql
CREATE TABLE cities (
  id         SMALLSERIAL PRIMARY KEY,
  slug       TEXT NOT NULL UNIQUE,          -- 'abuja', 'lagos'
  name       TEXT NOT NULL,
  is_active  BOOLEAN NOT NULL DEFAULT true
);
CREATE TABLE categories (
  id         SMALLSERIAL PRIMARY KEY,
  slug       TEXT NOT NULL UNIQUE,          -- 'camera','lens','lighting','audio','drone','gimbal','accessory'
  name       TEXT NOT NULL,
  checklist_template JSONB NOT NULL,        -- per-category handover template (serial-based vs count-based)
  is_active  BOOLEAN NOT NULL DEFAULT true

```
Data: seed `abuja` (active), `lagos` (active, launch-gated in app config). Seed the seven categories. `assets.city` and `assets.category` become `city_id` / `category_id` FKs; drop the `city` and `assetcategory` Postgres enums after backfill.

### 2.2 Catalogue

```sql
CREATE TABLE catalogue_items (
  id                     UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category_id            SMALLINT NOT NULL REFERENCES categories(id),
  make                   TEXT NOT NULL,
  model                  TEXT NOT NULL,
  mount                  TEXT,                       -- 'E','RF','L','MFT', null for non-optics
  specs                  JSONB NOT NULL DEFAULT '{}',
  replacement_value_band CHAR(1) NOT NULL CHECK (replacement_value_band IN ('A','B','C')),
  aliases                TEXT[] NOT NULL DEFAULT '{}',
  is_active              BOOLEAN NOT NULL DEFAULT true,
  created_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (make, model)
);
CREATE INDEX ix_catalogue_items_search ON catalogue_items
  USING gin (to_tsvector('simple', make || ' ' || model || ' ' || array_to_string(aliases, ' ')));
```
`assets` gains `catalogue_item_id UUID NOT NULL REFERENCES catalogue_items(id)`, `condition_grade TEXT CHECK (condition_grade IN ('excellent','good','fair'))`, `included_accessories JSONB NOT NULL DEFAULT '[]'`, `weekend_rate NUMERIC(12,2)`, `weekly_rate NUMERIC(12,2)`, `fulfilment JSONB NOT NULL DEFAULT '{"pickup":true,"delivery":false}'`. `assets.name` becomes nullable (display override only). An asset **is** a unit: one serial, quantity 1. Multiple units of the same model are multiple assets.

Backfill: existing assets get a catalogue row created from `name` with band 'B' and a `needs_review` flag in `specs`.

### 2.3 Trust tiers

`kyc_profiles.tier` semantics change to 0–3:

| Tier | Requirement | Unlocks |
|---|---|---|
| 0 | phone verified | browse |
| 1 | national ID + liveness + address (all via provider) | band A |
| 2 | Tier 1 **and** (≥3 completed bookings with no incident **or** one `vendor_reference` row) | band B |
| 3 | Tier 2 **and** per-booking `vendor_approval` | band C, on that booking only |

Add `vendor_references (id, renter_id, vendor_id, booking_id, created_at, UNIQUE(renter_id, vendor_id))`. Tier 2 is **computed**, not stored: `tier_effective()` in the service layer; `kyc_profiles.tier` stores the verified level (0/1) only. Tier 3 is a column on `bookings`: `vendor_approved_at TIMESTAMPTZ`.

Booking guard: `catalogue_items.replacement_value_band` vs renter's effective tier, enforced in the service and asserted in a test.

### 2.4 Booking state machine

Replace `bookingstatus` enum values with:

`requested, accepted, deposit_paid, confirmed, in_progress, returned, completed, declined, expired, cancelled_by_renter, cancelled_by_vendor, disputed, lost`

Add columns: `hold_expires_at TIMESTAMPTZ`, `deposit_due_at TIMESTAMPTZ`, `claim_window_ends_at TIMESTAMPTZ`, `price_snapshot JSONB NOT NULL` (rate basis, daily/weekend/weekly rate used, delivery fee, deposit, commission rate at request time), `fulfilment_choice TEXT NOT NULL`, `vendor_approved_at TIMESTAMPTZ`.

Exclusion constraint widened — a live request holds the unit:
```sql
ALTER TABLE bookings DROP CONSTRAINT ex_bookings_no_active_asset_overlap;
ALTER TABLE bookings ADD CONSTRAINT ex_bookings_no_live_overlap
  EXCLUDE USING gist (asset_id WITH =, daterange(starts_on, ends_on, '[]') WITH &&)
  WHERE (status IN ('requested','accepted','deposit_paid','confirmed','in_progress','returned'));
```
`expired`, `declined`, `cancelled_*` release the slot by leaving the WHERE set. `returned` still blocks until `completed` because of the claim window and the turnaround buffer.

`availability_windows` gains the same exclusion against itself for `is_blocked = true` rows, and the booking service checks blocked windows before inserting a request.

### 2.5 Ledger (append-only)

```sql
CREATE TABLE ledger_entries (
  id            BIGSERIAL PRIMARY KEY,
  booking_id    UUID REFERENCES bookings(id),
  payment_id    UUID REFERENCES payments(id),
  account       TEXT NOT NULL,       -- 'renter_deposit_liability','platform_cash','vendor_payable','platform_revenue','protection_pool','processing_fees'
  direction     CHAR(2) NOT NULL CHECK (direction IN ('dr','cr')),
  amount        NUMERIC(12,2) NOT NULL CHECK (amount > 0),
  currency      CHAR(3) NOT NULL DEFAULT 'NGN',
  txn_group     UUID NOT NULL,       -- every event writes ≥2 rows sharing one group; sum(dr)=sum(cr) per group
  memo          TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_ledger_booking ON ledger_entries(booking_id);
CREATE INDEX ix_ledger_group   ON ledger_entries(txn_group);
CREATE FUNCTION reject_mutation() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN RAISE EXCEPTION 'ledger_entries is append-only'; END $$;
CREATE TRIGGER trg_ledger_no_update BEFORE UPDATE OR DELETE ON ledger_entries
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();
```
A deferred constraint trigger asserts `sum(dr) = sum(cr)` per `txn_group` at commit.

Balances are derived: `deposits_held = SUM(cr) − SUM(dr) on renter_deposit_liability`. The `payments` table keeps provider state; it is not the source of truth for money.

### 2.6 Audit and webhooks

```sql
CREATE TABLE audit_events (
  id          BIGSERIAL PRIMARY KEY,
  actor_id    UUID REFERENCES users(id),      -- null for system/timer
  actor_role  TEXT NOT NULL,                  -- renter|vendor|admin|system
  entity      TEXT NOT NULL, entity_id UUID NOT NULL,
  action      TEXT NOT NULL,                  -- 'booking.accepted', 'deposit.released', ...
  before      JSONB, after JSONB, reason TEXT,
  request_id  TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- same reject_mutation trigger
CREATE TABLE webhook_events (
  id            BIGSERIAL PRIMARY KEY,
  provider      TEXT NOT NULL, provider_event_id TEXT NOT NULL,
  payload       JSONB NOT NULL, signature_ok BOOLEAN NOT NULL,
  received_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  processed_at  TIMESTAMPTZ, processing_error TEXT,
  UNIQUE (provider, provider_event_id)        -- idempotency
);
```

## 3. Booking module — service and API

### 3.1 Transitions

| From | Event | To | Guard | Side effects |
|---|---|---|---|---|
| — | `request` | requested | renter effective tier ≥ band; no blocked window; no live overlap (DB) | `hold_expires_at = now()+4h`; `price_snapshot` frozen; audit; notify vendor |
| requested | `accept` (vendor) | accepted | before hold expiry | `deposit_due_at = now()+12h`; audit; notify renter |
| requested | `decline` (vendor) | declined | — | audit; notify renter with alternatives |
| requested | timer | expired | `now() > hold_expires_at` | audit; notify renter; vendor response-rate metric |
| accepted | `deposit_captured` (webhook) | deposit_paid → confirmed | amount = snapshot deposit (+ waiver if chosen) | ledger: dr platform_cash / cr renter_deposit_liability; audit; notify both; release contact details |
| accepted | timer | expired | `now() > deposit_due_at` | slot released; audit; notify both |
| confirmed | `cancel` (renter) | cancelled_by_renter | before `starts_on` per policy | ledger refund per policy; audit |
| confirmed | `cancel` (vendor) | cancelled_by_vendor | any time | full refund; vendor reliability penalty; audit |
| confirmed | `handover_completed` + `balance_captured` | in_progress | both handover signatures **and** balance captured | ledger: dr platform_cash / cr vendor_payable (rental+delivery) and cr platform_revenue (commission) split at capture; audit |
| in_progress | `return_completed` | returned | both return signatures | `claim_window_ends_at = now()+24h`; audit |
| returned | `claim_raised` (vendor) | disputed | within claim window | freeze payout and deposit; audit; ops alert |
| returned | timer | completed | `now() > claim_window_ends_at` and no claim | ledger: deposit released (dr liability / cr platform_cash out), payout eligible; audit; notify both |
| disputed | `resolve` (admin) | completed | reason required | ledger entries per decision (deduct/forfeit/release); audit |
| in_progress | timer T+48h no contact | at_risk flag (column, not state) | — | freeze renter; ops alert |
| in_progress | `mark_lost` (admin) at ≥T+7d | lost | reason required | deposit forfeited to vendor; renter blacklisted; audit |

Every transition is one function in `app/services/booking.py` taking `(booking_id, actor, event, payload)`, executed in one DB transaction with `SELECT … FOR UPDATE` on the booking row. Illegal transitions raise `InvalidTransition` (HTTP 409).

### 3.2 Timers

A single scheduled job every minute: expire holds, expire deposit windows, complete returned bookings past the claim window, flag at-risk. Idempotent; each action is itself a transition with `actor_role='system'`.

### 3.3 Endpoints (`/api/v1`)

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/bookings` | renter | body: asset_id, starts_on, ends_on, fulfilment, waiver:boolean → 201 with state `requested` |
| POST | `/bookings/{id}/accept` · `/decline` | vendor | 409 if hold expired |
| POST | `/bookings/{id}/cancel` | renter/vendor | policy applied server-side |
| POST | `/bookings/{id}/handover` · `/return` | either | creates/updates `handover_records`; completes when both signed |
| POST | `/bookings/{id}/claim` | vendor | within window; body: amount, description, evidence |
| POST | `/bookings/{id}/resolve` | admin | body: decision, reason |
| GET | `/bookings/{id}` | party or admin | includes `money_line` object (see 3.4) |
| GET | `/me/home` | renter | active booking card + past bookings |
| GET | `/vendor/home` | vendor | new requests with `hold_expires_at`, today's handovers/returns, next payout, 7-day utilisation |
| GET | `/catalogue/search?q=&city=&from=&to=` | any | only assets with no live overlap in range; equivalents on empty |
| POST | `/webhooks/{provider}` | — | signature check → `webhook_events` insert (idempotent) → transition |

### 3.4 The money line

Every booking response carries:
```json
"money_line": {
  "deposit": {"amount": "150000.00", "status": "held|due|released|deducted|forfeited", "held_by": "platform"},
  "rental":  {"amount": "45000.00",  "status": "due_at_handover|received|paid_out"},
  "next":    {"label": "Handover Fri 10 Oct 10:00", "amount_due": "45000.00"}
}
```
Computed from the ledger and the booking state; never stored.

## 4. Identity and provider seams

- **Phone OTP:** `POST /auth/otp/request`, `POST /auth/otp/verify` → JWT. Rate-limited (5/phone/hour). Provider behind `OtpSender` interface; fake in dev.
- **`KycProvider` interface:** `verify_identity(id_type, id_number, selfie) -> VerificationResult`; `verify_address(doc) -> VerificationResult`. Fake returns configurable outcomes. Real adapter is a later milestone; provider not yet chosen.
- **`PaymentProvider` interface:** `create_virtual_account(booking_id, amount, purpose) -> VirtualAccount`; `initiate_payout(recipient_code, amount, reference)`; `verify_webhook(signature, body) -> bool`; `parse_event(body) -> PaymentEvent`. Fake implementation drives the full state machine in tests with no network.
- Service code depends only on the interfaces. Paystack adapter lands when the provider contract is signed (Q4).
